# Contributing

Thanks for taking the time. This project has one maintainer, so here's how to make your contribution easy to accept.

## Before you write code

Open an issue first for anything bigger than a typo. Say what you want to change and why. That way we can agree on the approach before you spend time on it.

## Pull requests

- Keep each PR to one change.
- Add or update tests for any change in behaviour.
- Make sure CI passes. Workflows on PRs from forks run once the maintainer approves them.
- PRs are squash-merged, so the PR title becomes the commit message. Write it as a short sentence saying what the change does.

Merging and releases are at the maintainer's discretion. A PR can be closed if it doesn't fit the project's direction, even when the code is good.

## Security issues

Don't open a public issue. See [SECURITY.md](SECURITY.md).
